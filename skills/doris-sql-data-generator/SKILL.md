# Doris 测试数据生成器

根据用户输入，自动从 Doris 获取表结构，生成符合业务逻辑的造数脚本。

## 核心原则

1. **数据要有业务语义**——不要生成 `name1`, `name2` 之类无意义的枚举值，根据列名生成贴合业务的真实感数据（如姓名、手机号、日期、金额、状态枚举）
2. **关联键必须匹配**——如果表 A 与表 B 通过 `user_id` JOIN，两表的 `user_id` 值域必须有重叠（取交集而非全独立生成）
3. **WHERE 条件可命中**——生成的模拟数据中，30-70% 的行应满足用户 SQL 中的 WHERE 过滤条件，以模拟真实选择性
4. **数据量级符合预期**——默认推荐 10 万行，造数脚本按批次执行（每批 500-1000 行），避免单条 SQL 过大
5. **区分度足够**——不要在关联键/分组键上生成无区分度的值（如全为 1），要确保 GROUP BY 能产生多条

## 工作流

### Step 1: 理解输入，提取信息

根据用户输入，做三件事：

**1a. 提取表名**
- 如果用户给了 SQL，用正则提取 `FROM` / `JOIN` / `UPDATE` / `INSERT INTO` 后的表名（支持 `db.table` / `catalog.db.table`）
- 如果用户直接说了表名，按用户指定的来
- 如果用户只说了业务描述（如"生成订单表和用户表的数据"），问清楚表名和字段结构

**1b. 明确数据逻辑**
一次性问清以下问题（不要挤牙膏）：
- **数据量级**：每条表需要多少行？（默认推荐 10 万行，压测场景可到 100 万-1000 万行）
- **关联逻辑**：如果涉及多表，表间 JOIN 关系是什么？关联键的取值范围有什么限制？
- **过滤条件**：数据是否需要满足某些 WHERE 条件（如 `status = 1`、`create_time >= '2026-01-01'`）？
- **特殊要求**：是否有特定的数据分布需求（如倾斜、边界值、NULL 比例）？

### Step 2: 获取表结构

优先通过 MCP 工具获取结构，按以下优先级：

**首选**: `doris_get_table_schema(table_name, db_name)` — 获取完整 DDL 和字段信息
**补充**: `doris_get_table_basic_info(table_name, db_name)` — 了解现有行数和分区情况（可选）
**兜底**: 如果 MCP 不可用，请用户直接贴建表语句

获取到的信息包括：
- 字段名、数据类型、是否可为 NULL、默认值
- 分区键、分桶键、主键/唯一键
- 字段注释（如果有，按注释语义生成数据）

### Step 3: 设计数据生成方案

在生成脚本前，先输出一份简要方案让用户确认：

```
## 数据生成方案
### 表清单
- <db.table1> —— N 行
- <db.table2> —— N 行

### 关联关系
- table1.user_id ↔ table2.user_id（取值 1-10000，两表取交集）

### 关键字段生成逻辑
| 表 | 字段 | 类型 | 生成策略 |
|----|------|------|---------|
| table1 | user_id | BIGINT | 从 1 递增至 10000 |
| table1 | status | TINYINT | 随机 0/1，30% 为 0，70% 为 1 |
| table1 | create_time | DATETIME | 2026-01-01 至 2026-06-01 随机 |
| table2 | user_id | BIGINT | 从 1-10000 中随机取 5000 个 |
| table2 | amount | DECIMAL | 随机 10.00-9999.99 |

### WHERE 条件命中策略
- SQL 中 `status = 1` → 让 70% 的数据满足
- SQL 中 `create_time >= '2026-01-01'` → 所有行均满足（100%）

**如果生成方案没问题，我将输出 DDL + DML 文件。需要调整吗？**
```

用户确认后再进入下一步。

### Step 4: 生成 DDL 文件

在项目根目录下创建 `mock-data/ddl/` 目录。

每个表生成一个独立的 DDL 文件，命名：`<db>_<table>.sql`

DDL 文件内容：
```sql
-- ============================================
-- 测试数据 - 建表语句
-- 生成时间: 2026-06-01 14:30:00
-- 数据量级: <table>: 100000 rows
-- ============================================

CREATE TABLE IF NOT EXISTS <db>.<table> (
    id BIGINT NOT NULL,
    user_id BIGINT NOT NULL,
    ...
) ENGINE=OLAP
DUPLICATE KEY(id)
DISTRIBUTED BY HASH(id) BUCKETS 10
PROPERTIES (
    "replication_num" = "1"
);
```

DDL 关键规则：
- 从 `doris_get_table_schema` 获取原表结构，保持列名、类型、分区分桶不变
- **分桶数可简化**：造数场景默认 `BUCKETS 10`（除非用户明确要求按原分桶策略）
- **副本数设为 1**（`replication_num = "1"`），造数场景不需要多副本
- 添加 `IF NOT EXISTS` 避免重复执行报错
- 表名保持原表名不变（无需加 `_shadow` 后缀——这是造数据工具，不是影子表）

### Step 5: 生成 DML 文件

在项目根目录下创建 `mock-data/dml/` 目录。

DML 文件命名：`mock_data_<YYYYMMDD_HHMMSS>.sql`

DML 文件内容结构：
```sql
-- ============================================
-- 测试数据 - 数据插入脚本
-- 生成时间: 2026-06-01 14:30:00
-- 表清单: db.table1 (100000 rows), db.table2 (50000 rows)
-- ============================================

-- ====================
-- 1. db.table1 (100000 rows)
-- ====================
INSERT INTO db.table1 (id, user_id, name, status, create_time) VALUES
(1, 101, '张三', 1, '2026-01-15 10:30:00'),
(2, 102, '李四', 0, '2026-02-20 14:15:00'),
...

-- ====================
-- 2. db.table2 (50000 rows)
-- ====================
INSERT INTO db.table2 (id, user_id, amount, order_time) VALUES
...
```

#### 造数编码要点

DML 数据生成应使用**循环 + 值列表**的方式在脚本中生成，通过多个 `INSERT INTO ... VALUES` 分批插入，每批 500-1000 行。

每种数据类型的具体生成策略：

| 数据类型 | 生成策略 | 示例 |
|---------|---------|------|
| `TINYINT/SMALLINT/INT/BIGINT` | 从固定范围递增或随机，关联键取交集 | `user_id`: 1-100000 |
| `DECIMAL/DOUBLE/FLOAT` | 按金额/分数等业务含义随机 | `amount`: ROUND(RAND() * 10000, 2) |
| `VARCHAR/STRING` | 从预定义名字典中循环取 | 姓名：`['张三','李四','王五',...]` |
| `DATETIME/DATE` | 按业务时间范围随机 | `create_time`: '2026-01-01' + INTERVAL RAND()*150 DAY |
| `BOOLEAN/TINYINT(1)` | 按比例分布 | `status`: IF(RAND()>0.3, 1, 0) |
| `JSON` | 构造简单 JSON 字符串 | `CONCAT('{"key":"', name, '"}')` |
| `BIGINT 作为枚举` | 从有限值集合中随机 | `type`: [1,2,3,4,5] 随机取 |

#### 跨表关联键生成策略

这是最关键的部分——关联键必须「对接」得上：

**单值关联（如 user_id ↔ user_id）：**
```
-- 先定义一个关联键值池（在所有表中共用）
-- 思路：关联键的取值范围在两表中取其交集
-- 假设两表都需要 user_id，主表 A 用 1-100000，从表 B 也取 1-100000 的子集

-- 表 A: user_id 从 1 递增到 100000
-- 表 B: user_id 从随机取 50000 个，范围也是 1-100000
```

**多字段关联（如 date + user_id）：**
```
-- 先确保组合键在两个表中同时出现
-- 每个表在生成时使用相同的随机种子或按 join 键固定取值范围
```

#### 业务词典推荐

常用的中文业务值列表（按列名匹配）：

| 列名关键词 | 推荐值 |
|-----------|--------|
| `name`, `user_name`, `nickname` | 张三, 李四, 王五, 赵六, 陈七, 刘八 |
| `phone`, `mobile`, `tel` | 13800138000 + i, 13900139000 + i |
| `email` | user_{i}@example.com |
| `city`, `city_name` | 北京, 上海, 广州, 深圳, 杭州, 成都 |
| `status`, `state` | 0/1/2 按比例 |
| `type`, `category`, `kind` | 1-10 随机 |
| `gender`, `sex` | 男, 女 / 0, 1 |
| `age` | 18-60 随机 |
| `amount`, `price`, `money`, `fee` | 10.00-9999.99 |
| `score`, `grade` | 0-100 |
| `date`, `time`, `create_time` | 按业务范围 |

### Step 6: 输出确认

将生成的 DDL 和 DML 文件路径告诉用户：

```
✅ 造数文件已生成：

📁 mock-data/ddl/
  ├── db_orders.sql       — 订单表建表
  └── db_users.sql        — 用户表建表

📁 mock-data/dml/
  └── mock_data_20260601_143000.sql  — 数据插入脚本

执行顺序：
1. 先用 DDL 建表（在 Doris 中执行）
2. 再执行 DML 插入数据
```

可选跟进：
- "需要我在 Doris 中直接执行这些脚本吗？"
- "数据量级是否需要调整？"
- "是否需要补充更多表的数据？"

## 执行确认

在生成脚本后，建议（但不是必须）问用户是否要在当前连接的 Doris 环境中执行。

如果用户确认执行：
1. 先执行 DDL 建表
2. 再分批执行 DML，每批完成后告知进度
3. 最后建议执行 `ANALYZE TABLE <表名> WITH SYNC MODE;` 更新统计信息（仅建议，不强求）

## 工具参考

| 工具 | 用途 | 使用时机 |

| `doris_get_table_schema` | 获取表完整结构（DDL + 字段） | Step 2（首选） |

## 注意事项

1. **不要触发性能分析流程**——如果用户同时提到造数据和性能优化，先问用户"你是主要想做性能分析，还是先造数据？"然后走对应流程
2. **关联键匹配是核心难点**——多表造数时，务必检查各表的关联字段是否在相同的值域内生成。一个常见的错误是两张表的 `user_id` 分别从 1 递增，导致 JOIN 后无匹配行
3. **数据量 10 万行起步**——功能验证可以少（1000 行），但压测或性能验证场景需要 10 万行以上才能反映真实情况
4. **Schema 获取失败时向用户说明**——如果 MCP 工具无法连接或查询超时，清晰地告知用户并提供替代方案（如贴建表语句）
5. **DDL 文件是独立的**——每个表一个文件，方便用户选择性执行
6. **DML 文件按批次组织**——每批 500-1000 行 VALUES，每批之间用注释分隔，方便用户按批执行监控错误
